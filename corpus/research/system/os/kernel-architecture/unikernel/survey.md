# Unikernels as a Redistribution of OS Obligations

## Thesis

Unikernels belong in kernel-architecture research because they change **which application knowledge the OS can use, which computations share authority, and where the remaining OS responsibilities live**. Removing general-purpose guest machinery can simplify an appliance, but resource arbitration, protection, compatibility, scheduling, persistence and recovery still need implementations. The useful question is therefore which obligation disappears under a narrower contract, and which moves to application code, a runtime, the host or the control plane.

This connects the subtopic to the [broader kernel survey](../survey.md)'s customization, isolation, sharing and state-continuity problems. Library OS, unikernel and process-backed appliance are overlapping architectural ideas, not interchangeable deployment forms. [Exokernel](<../../../../../../.obsidian/zotero/pdfs/TUYHH9IZ.pdf>), [ExOS](<../../../../../../.obsidian/zotero/pdfs/H6IKQVLH.pdf>) and [Drawbridge](<../../../../../../.obsidian/zotero/pdfs/EWAG9YKM.pdf>) provide lineage there; they are not retrospectively cloud unikernels or new complete readings in this pass.

Four architectural decisions prevent the label from doing too much explanatory work:

| Architecture axis | Alternatives | Consequence |
|---|---|---|
| Application contract | Rewritten or recompiled source; executable ABI; selected POSIX behavior | A port, protocol subset and unchanged binary preserve different behavior. |
| Sharing and authority | Trusting program/family/workflow; isolated components or processes | Address spaces and modularity alone do not establish protection. |
| Execution substrate | Hypervisor guest; host process; hosted/native combination; enclave | Scheduling, devices and tenant protection remain at different boundaries. |
| Specialization time | Build; load; initialization; request; live reconfiguration | Selection, snapshots, lazy loading and replacement preserve different state. |

Mirage's 2013 prototype is cooperative and single-vCPU; OSv has dynamic linking and preemptive SMP threads; Nabla uses a host process; Graphene retains separate address spaces. These differences are central to their contracts, not exceptions to one canonical shape ([C1](<../../../../../../.obsidian/zotero/pdfs/SWL9NIL7.pdf>), [S1](<../../../../../../.obsidian/zotero/pdfs/Q6T4UYJP.pdf>), [S3](#^s3), [S9](<../../../../../../.obsidian/zotero/pdfs/V283ZHT3.pdf>)).

## Mechanism similarities

Three recurring transformations explain more than project families. First, **narrow the required behavior and expose implementation choices**. Mirage changes the source/service contract; Loupe tests omissions against an oracle; Wayfinder searches available configurations. Reusing Linux or NetBSD instead preserves substantial existing implementation. These routes may cooperate, but requirement inference, construction and optimization are distinct achievements.

Second, **bring information and control closer while choosing who may cooperate**. EbbRT's ownership APIs, UKL's expert shortcuts and uCache's callbacks let an application avoid generic decisions. AlloyStack instead makes a trusting workflow the sharing unit. FlexOS restores selected boundaries within an appliance. Their cheaper interactions may reflect application knowledge, cheaper enforcement or increased trust; those explanations must remain separate.

Third, **share contents while reconstructing private identity**. SEUSS retains initialized templates; Nephele shares VM pages but recreates backend resources; μFork copies and relocates pages on child capability loads as well as writes ([C7](<../../../../../../.obsidian/zotero/pdfs/DMYRKUIV.pdf>)). Similar copying language hides different invariants. Equal bytes do not establish correct pointers, independent queues or replay-safe external effects. Jitsu's overlap and ownership handoff is another lifecycle transformation, rather than generic checkpoint reuse. These are structural comparisons, not claims of direct influence.

## Decisive evidence and counterexamples

1. **Co-location does not automatically produce an equivalent faster program.** Unikraft's lwIP KV composition reports 319K requests/s against a Linux guest's 418K. Its rewritten path approaches DPDK performance after removing the stack/scheduler, with different guest-core budgets. UKL's Redis gain is 1.6% in the base configuration versus 26% after expert shortcuts. Mirage's DNS gain depends on memoization; EbbRT's rewritten memcached omits features. These gains depend on application knowledge and code changes ([C1](<../../../../../../.obsidian/zotero/pdfs/SWL9NIL7.pdf>)–[C3](<../../../../../../.obsidian/zotero/pdfs/4WY5CTU3.pdf>), [S14](<../../../../../../.obsidian/zotero/pdfs/LHEBKZLF.pdf>)).

2. **Passing a test does not establish acceptable omissions.** Loupe can improve Nginx throughput by removing access logging, preserve tested Redis KV operations while breaking persistence through `pipe2` suppression, or leak descriptors by suppressing `close`. Wayfinder optimizes its supplied measurements, with representative environments and deployment review still required. Neither supplies production semantic completeness ([C4](<../../../../../../.obsidian/zotero/pdfs/LJZQWVUH.pdf>)–[C5](<../../../../../../.obsidian/zotero/pdfs/7ZAQQ9MD.pdf>)).

3. **Restoring one process operation does not restore every execution contract.** μFork requires compatible pure-capability/PIC recompilation; shared libraries and shared memory remain extensions, and stable Nginx results are single-core. Nephele reconstructs selected Xen devices, whereas Graphene coordinates independent process states. HermiTux lacks `fork`; Occlum uses `spawn`. These are alternative bounded contracts, not successive percentages of universal compatibility ([C7](<../../../../../../.obsidian/zotero/pdfs/DMYRKUIV.pdf>), [C11](<../../../../../../.obsidian/zotero/pdfs/4RFLYHQQ.pdf>), [S2](#^s2), [S9](<../../../../../../.obsidian/zotero/pdfs/V283ZHT3.pdf>), [S12](<../../../../../../.obsidian/zotero/pdfs/HLTVYYDP.pdf>)).

4. **Smaller interfaces and compartments are different security results.** Nabla's kernel-reachability measurement is not VM-equivalent security proof. FlexOS's MPK prototype has a common shared heap; a gate does not establish safe aliasing. CubicleOS closes ACL grants promptly but updates hardware page tags lazily; complete control-flow protection needs proposed hardware. AlloyStack normally trusts same-workflow functions. Threat models and enforcement over both calls and objects determine the comparison ([S3](#^s3), [C6](<../../../../../../.obsidian/zotero/pdfs/TQ63BR9B.pdf>), [S8](<../../../../../../.obsidian/zotero/pdfs/MYEHU9YB.pdf>), [C8](<../../../../../../.obsidian/zotero/pdfs/8DNJN339.pdf>)).

5. **Cheap startup does not predict useful service performance.** LightVM's 2.3-ms result uses a prepared no-op/no-device guest; its 8,000-instance density uses idle guests. Its TLS unikernel boots faster and uses less memory than Tinyx yet delivers about one fifth of the throughput. SEUSS's 7.5-ms internal cold invocation starts from a ready runtime snapshot and excludes the external control/network path; Linux wins its smallest mostly-hot sets. Nephele's full tiny UDP clone takes 20–30 ms, mostly Dom0. Measure preparation, first response, steady work and teardown separately ([C9](<../../../../../../.obsidian/zotero/pdfs/EVVJHSXQ.pdf>)–[C11](<../../../../../../.obsidian/zotero/pdfs/4RFLYHQQ.pdf>)).

## Research questions and reading

Three questions follow from the compared mechanisms; they are proposed investigations rather than established novel gaps:

- **When must a specialization be revised?** Connect requirement inference and configuration search to explicit functional, security and resource acceptance as workloads, failures and upgrades change.
- **How can cheap sharing retain enforceable ownership?** Compare windows, shared heaps, capabilities and SFI over grant lifetime, mutation, revocation and recovery, rather than gate cycles alone.
- **Which execution state can be reused safely?** Include descriptors, queues, identities, reserved resources and non-idempotent effects when comparing snapshots or clones.

Promote HermiTux/Nabla to full close readings next, then Cozart/Linux API usage/Junction. For each comparison fix behavior, trust, charged resources, timing endpoints, code changes and validation before interpreting a gain.
